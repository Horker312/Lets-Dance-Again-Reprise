# LDA:R 0.5.5 — 원본 구도 보정 구현·배포 후보 검증

**상태: 소스 수정·DLL 빌드·오프라인 검사 완료. 실제 Skyrim 화면 검증 전 배포 후보.**

## 1. 기존 구조에서 확인한 문제
현재 샘플 좌표는 게임 월드 좌표가 아니라 스켈레톤 모델 로컬/무대 좌표입니다. Exporter는 카메라 본을 rig.World로 평가하고 프로젝트의 무대 방향을 역변환해 저장합니다. 이름의 “source rig world space”는 실제 Skyrim 월드 공간이 아닙니다.
검사한 Booo 춤/카메라는 모두 extractedMotion 없음, 원점 NPC Root 위치 (0,0,0)·스케일 1 고정, FOV float 0개, annotation event 0개였습니다.
춤의 COM·골반은 안무로 이동합니다. 카메라 HKX의 COM에는 약 -999998의 숨김용으로 보이는 Z가 있어 캐릭터의 월드 기준점으로 사용하면 안 됩니다. 실제 선택 카메라 본은 독립 모델 좌표입니다.
따라서 이 자료에서 COM/골반을 현재 플레이어 위치에 추가하거나 다시 빼면 이중 이동/잘못된 원점을 만들게 됩니다. 원본 안무의 이동은 포즈와 카메라에 남겨 둡니다.
0.5.4의 기본 XYZ 비례 변환 자체는 맞지만, 매 평가에서 애니메이션된 노드의 월드 배율을 다시 읽고 사용자 효과 기준을 첫 프레임으로 잡는 부분이 불안정했습니다. 좌표계/원본 기준점/cut의 계약도 충분히 명시되지 않았습니다.

## 2. 적용 공식·좌표계
평가 순서: 음악 샘플 시계 → 변경하지 않은 카메라 키 평가 → 명시된 원본 기준 포즈의 역변환 → 준비 때 캡처한 유효 스케일/원본 스케일 비율 → 선택적 사용자 이동 강도 → 현재 플레이어 위치·월드 기준 방향 → 마지막 월드 Z 높이.
기본 공식은 `Pnew + Qnew × [S × Qref^-1 × (Cref-Pref)] + (0,0,H)`입니다. 방향은 `Qnew × Qref^-1 × 원본 카메라 방향`에 기존 게임 좌표계 캘리브레이션만 적용합니다. 자동 Look-at은 없습니다.
기존 actor-local 파일은 이미 정규화되어 있으므로 Pref=0, Qref=항등, 원본 기준 스케일=1로 읽습니다. 불필요한 추가 COM 추적/정규화는 넣지 않습니다.
준비 중 애니메이션을 바꾸기 전에 NPC Root 월드 배율 → 모델 루트 월드 배율 → BaseHeight → GetScale의 기존 선택 순서로 한 번 확보합니다. 이미 합성된 값에 종족·참조 스케일을 다시 곱하지 않습니다. 안무 도중 노드가 움직이거나 배율이 변해도 세션 배율은 바뀌지 않습니다.
준비 후 체형을 바꿨다면 중지·재준비해야 합니다. 개별 신체 노드 비균일 변형/특수 스켈레톤을 이 한 배율로 완벽히 맞춘다고 주장하지 않습니다.

## 3. 이전 구현과 차이
- 매 프레임 배율 재측정 → 세션 시작 전 준비 단계에서 안정적으로 캡처.
- 첫 프레임 사용자 효과 기준 → 명시 movementPivot 우선, 없으면 전체 경로의 시간 가중 평균. 이것은 사용자 연출을 위한 수학적 중심이며 원작자의 기준점이라고 표시하지 않습니다.
- 별도 촬영 거리 배율 UI 제거. 이동 강도 100%는 기준점과 관계없이 원본 XYZ 비례 변환을 직접 계산합니다. 스케일만으로 이동 강도를 추가 과장하지 않습니다.
- 플레이어의 실제 위치뿐 아니라 월드 기준 방향 변경도 위치/카메라 방향에 같은 변환으로 반영합니다. 렌더 직전 변경분도 동일한 게시 스냅샷에 한 번 재기준화하며 다음 프레임의 원본 입력으로 누적하지 않습니다.
- Z 전용 배율은 새 실행 경로에서 호출하지 않습니다. 높이 오프셋은 최종 월드 Z에 한 번 더합니다.
- 명시적인 카메라 컷과 원본 캐릭터 기준점 컷을 구분합니다. 카메라가 컷한다고 원본 캐릭터 이동까지 멈추지 않습니다. 데이터에 없는 컷은 추정하지 않습니다.

## 4. 실제 수정 파일·기능
- runtime/CameraStage.h: 순수 상대좌표 변환, 세션 배율, 월드 높이, 위치·방향 재기준화.
- runtime/TrackData.h: 기존 v1/v2 계약 유지, v3 명시 좌표계·기준 포즈·원본 스케일·사용자 효과 기준점·cut/referenceCut 해석.
- runtime/plugin.cpp: 단일 변환 경로 연결, 배율 캡처, 플레이어 즉시 위치/방향 추적, Photo Mode 인계 위치 일치와 진단 로그.
- runtime/CameraFramingSettings.h, SettingsMenu.h: 설정 스키마 2와 이전 사용자 효과 값 마이그레이션, 이동 강도 중심으로 UI 정리.
- localization/runtime/ko.json·en.json 및 생성 헤더: 한·영 안내/오류. 기존 준비 창 체크박스/휠 FOV 기능 유지.
- versions.json/생성 버전 파일: LDA:R 0.5.5, Dance Studio 0.5.0. 빌드로 자동 증가하지 않습니다.
- camera-framing-dev: 실제 HKX 조사용 probe, 이동 기준점/컷/왕복/기준점 변환/설정/화면 좌표 검사.

## 5. Dance Studio 수정 여부
제품 소스/실행 파일은 수정하지 않았습니다. 조사용 별도 probe만 기존 편집기 디코더를 참조합니다.
현재 실제 자료는 이미 모델 로컬 경로여서 기준 캐릭터의 움직임을 추가 추정할 필요가 없습니다. 원본 HKX에는 신뢰할 수 있는 FOV/cut annotation이 없어 이 정보를 새로 만들어 출력하는 기능을 넣지 않았습니다.
기존 출력은 변경 없이 재생합니다. 새 기준 포즈/컷 정보가 실제로 주어질 때 사용할 런타임 포맷은 v3로 명확히 구분했지만, 편집기가 이를 원본에서 추출했다고 주장하지 않습니다.
v3의 coordinateSpace=reference-world는 각 키에 referencePosition/referenceRotation을 요구합니다. referenceScale과 movementPivot도 명시할 수 있습니다. 일반 키는 기존 보간, cut=true는 그 키 시점까지 이전 카메라 포즈 유지, referenceCut=true는 원본 캐릭터 기준 포즈에 별도로 적용합니다. 이전 런타임은 v3를 거부하므로 필수 메타데이터를 무시하고 잘못 재생하지 않습니다.

## 6. 기존 곡·설정 마이그레이션
현재 정상 actor-local v1/v2 곡은 이 카메라 보정 때문에 재내보낼 필요가 없습니다. 남성 경로가 없는 예전 춤의 재내보내기 요구는 별개로 그대로입니다.
구 CameraFraming.json의 첫 프레임 기반 사용자 지정 거리·이동 강도는 100%로 초기화하고 안내합니다. 스케일 체크 상태와 곡의 수동 높이는 유지합니다. 기존 파일을 즉시 덮어쓰지는 않으며 새 이동 강도를 선택하거나 초기화 버튼을 눌러 저장하면 설정 스키마 2로 확정됩니다.
원본 HKX·음악·사용자 곡 패키지·키 설정은 수정하지 않았습니다.

## 7. 스케일별 수학·화면 좌표 검증
0.5 / 0.75 / 1.0 / 1.25 / 1.5 / 2.0을 검사했습니다. 기본 이동 강도 100%, 수동 높이 0에서 스케일 1의 원본 좌표를 유지합니다.
실제 HKX에서 721시점의 머리·상체·골반·양발을 추출하고, 같은 참조 모델을 균일 확대·축소한 이상적 투영 결과를 대조했습니다. 이는 실제 현재 플레이어를 게임에서 측정한 결과가 아닙니다.
기존 화면 구도·설정 검사 219,791개 통과. 화면 내 지점 33,000회와 원래 화면 밖인 지점 17,946회의 분류를 유지했습니다. 실제 HKX 자료가 포함된 화면 내 비교는 14,682회입니다.
관찰된 화면 내 최대 NDC 수치 오차는 9.6e-14입니다. 배정밀도 수학 결과이며 실제 렌더러의 부동소수점/클리핑 정밀도를 보장하는 숫자가 아닙니다.
의도된 클로즈업이나 원래 화면 밖에 있던 신체 지점을 전신 촬영으로 바꾸지 않았습니다.

## 8. 왕복·컷·재생 이력 검사
새 계약 검사 710개 통과: A→B→A / A→B→C→A, 역탐색/반복 평가, 이동 강도 100% 및 비기본값, 명시/평균 기준점, 배율 세션 캡처, 이동·회전·순간이동, 수동 높이, 명시 reference-world 변환과 카메라 컷/캐릭터 기준점 컷 분리, 설정 마이그레이션.
추가된 reference-world 이동 자료는 합성 검증용이며 실제 HKX에서 그런 메타데이터를 추출한 것처럼 보고하지 않습니다.
현재 실제 HKX에 명시적 컷 의미가 없으므로 기존 샘플 사이의 보간은 그대로 유지합니다. 큰 위치 차이를 컷이라고 추정하지 않습니다. 원본 영상과의 정확한 컷 경계 대조는 게임/원본 영상 확인이 필요합니다.

## 9. 빌드·회귀·런타임 결과
0.5.5 DLL 컴파일/버전 리소스/링크 성공. SKSE Load/Query/Version export와 설치된 세 버전의 Address Library 후킹 ID 수록 여부를 확인했습니다.
공통 계산은 CommonLib와 독립된 순수 C++ 함수입니다. 새 게임 구조체 오프셋이나 실행 버전별 추가 후킹 주소를 도입하지 않았습니다.
1.5.97 / Steam 1.6.640 / Steam 1.6.1170을 명시하는 단일 SE+AE 빌드입니다. **세 버전 모두 이번 작업에서 실제 게임을 실행하지 않았습니다.** AE 두 버전은 시험 지원입니다.
네이티브 준비/정리·stale callback 3500개, 독립 콘텐츠 선택 31개, Space/단계/카메라 추적 정책 38개, Photo Mode 일시정지 정책 63개, 실제 WinMM 일시정지/재개 8개 검사 통과.
준비 창 체크박스·휠 FOV·복구 검사 142개 통과. 편집기의 음악 시간 매핑·독립 FPS·한영 전환 회귀 검사도 통과했습니다. 편집기는 재빌드/버전 변경 없이 기존 0.5.0을 사용합니다.

## 10. 배포 전 실제 게임 확인·제한
각 스케일에서 같은 곡·같은 음악 시점·같은 화면비를 캡처해 원본과 대조해야 합니다. 얼굴/상체/전신, 접근/후퇴, 원형/왕복/빠른 방향 전환, 컷 직전·직후를 확인하세요.
준비 후 크기 변경은 재준비가 필요합니다. 이동/회전/셀 전환, Space 재개, Photo Mode 점유/시간 정지/복귀, 강제 종료 후 카메라·입력·FOV 복구를 확인해야 합니다.
일반 종족이라도 실제 종족별 게임 검증을 마친 것은 아닙니다. 고유 스켈레톤·비균일 체형은 보장하지 않습니다.
HKX extractedMotion이 별도로 있는 다른 자료의 실제 월드 이동과 기존 actor-local 카메라의 관계는 검증하지 못했습니다. 명시 기준 정보가 없는 경우 캐릭터의 COM/골반으로 원본 이동을 추정해 보정하지 않습니다.
실제 게임의 근거리/원거리 클리핑, 카메라 렌더 좌표 오차, 원본 영상과의 시각 대조는 미검증입니다. 특히 매우 작은 캐릭터의 근접 클로즈업에서 엔진 클리핑이 남는다면 별도 원인 확인이 필요합니다.
HKX FOV float가 없는 자료는 원작자의 알 수 없는 FOV를 추정하지 않습니다. 기존 프로젝트/출력에 명시된 FOV를 유지하고 휠 입력만 사용자 임시 보정으로 처리합니다.
주변 구조물·벽·천장·배경·장소 자동 보정은 범위에서 제외했습니다. GitHub에 0.5.5 소스를 반영했습니다. 대응 소스 ZIP도 별도로 제공합니다.
