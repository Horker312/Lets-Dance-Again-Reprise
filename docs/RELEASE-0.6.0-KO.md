# LDA:R 0.6.0 공개 전 품질 개선 결과

구성: LDA:R 0.6.0 / Dance Studio 0.5.13 / Facial Studio 0.5.7. 설치 폴더에는 적용하지 않았습니다.
이 문서의 PASS는 명시된 코드·자동 검사 범위이며, Skyrim 시각적 재생 확인을 뜻하지 않습니다.

## Q1. 같은 곡 업데이트와 복구

Dance Studio 상단의 **기존 곡 업데이트**는 현재 프로젝트의 패키지 종류별 ID를 유지하고 새 exportId/리비전을 만듭니다. **새 곡으로 추가**는 독립 ID를 발급합니다. 시스템 시간이 뒤로 바뀌어도 기존 리비전보다 새 출력이 최신이 되도록 처리했습니다.

먼저 임시 폴더에 새 곡을 완성·검증한 뒤 이전 출력 경로를 보여 줍니다. 사용자는 **ZIP 백업 후 정리 / 이전 출력도 유지 / 취소**를 선택합니다. 정리 후보는 선택한 출력 상위 폴더의 직접 하위 폴더 중 프로젝트 ID·패키지 ID·종류가 일치하고 파일 목록과 해시를 확인한 출력뿐입니다. 다른 모드 경로를 검색해 삭제하지 않습니다. 사용자 추가 파일, 변경된 파일, 링크 경로는 자동 정리 대상에서 제외합니다.

정리 선택 시 `.LDA-R-backups/<고유값>.zip`에 이전 출력 전체를 저장하고 ZIP 내부 파일 SHA-256을 다시 확인한 뒤 새 폴더를 게시합니다. 게시 실패 시 이전 폴더는 유지합니다. 게시 성공 후에도 이전 폴더가 바뀌었거나 정리할 수 없으면 보존하고 경고합니다. 정리 중 오류로 `.LDA-R-retired-*` 폴더가 남을 수 있습니다. 백업 ZIP은 자동 삭제하지 않습니다.

복구: 게임을 종료하고 새 리비전 폴더를 다른 장소로 옮긴 다음, 백업 ZIP의 이전 곡 폴더를 원래 출력 상위 폴더에 풉니다. MO2의 다른 설치본을 대신 정리하지 않습니다. 게임 실행 중 내보내기는 거부합니다. OS 장애·전원 차단까지 원자적으로 복구하는 데이터베이스는 아니며, 검사 직후 게임을 실행하는 경쟁 상황을 프로세스 잠금으로 막지는 않습니다.

## Q2. 누락된 원본 다시 연결

춤 HKX·카메라 HKX·음악·사용자 스켈레톤의 누락 경로를 각각 표시하는 재연결 창을 추가했습니다. 사용자가 대체 파일을 직접 선택하며, 파일 크기와 SHA-256 기록이 있으면 동일/변경 여부를 표시합니다. 이름만 같은 파일을 자동 연결하지 않습니다. 이전 프로젝트에 지문 정보가 없으면 동일성을 확인할 수 없다고 표시합니다.

프로젝트 복사본에서 경로를 바꾸고 HKX·스켈레톤·트랙 범위를 검증한 후 열린 프로젝트에 반영합니다. 시간·배속·In/Out·표정 클립·강도 곡선·프로젝트/패키지 ID는 유지합니다. 취소·잘못된 파일에서는 현재 작업을 유지합니다. 사용자 지정 스켈레톤 누락을 내장 스켈레톤으로 몰래 대체하지 않습니다. 재연결 후 프로젝트를 저장하면 경로와 지문을 보관합니다.

## Q3. 곡·표정 오류 안내

표정 파일의 누락, 해시 불일치, 손상, 미지원 형식을 구분한 짧은 HUD 경고를 준비 완료 시 표시하고 로그에 기록합니다. 같은 곡·리비전·원인의 반복 알림은 제한합니다. 표정 오류는 표정 기능만 비활성화하며 음악·춤·카메라를 중단하지 않습니다.

곡 검색은 개별 오류를 격리하고 유효 곡/이전 리비전/충돌/잘못된 항목/한도 요약을 제공합니다. 최종 512곡 한도는 ID·리비전 정리 뒤 적용합니다. 검색 자체는 4096개 폴더 항목·메타데이터 합계 64MiB·협력적 8초 예산으로 제한됩니다. 파일 시스템의 한 번의 블로킹 I/O를 8초에 강제 중단하는 방식은 아닙니다. 선택 토큰 충돌은 관련 곡을 제외하고 정상 곡을 보존합니다. SHA-256의 대소문자 차이만으로 유효 곡이 거부되는 문제도 수정했습니다.

## Q4. 후킹 근거와 확인 범위

지원 대상은 Steam SE 1.5.97, AE 1.6.640, AE 1.6.1170입니다. 다른 실행 버전은 거부합니다. 기존 Address Library ID/오프셋은 임의 변경하지 않았습니다.

| 실행 버전 | Update ID + 오프셋 | Input ID + 오프셋 | Address Library RVA 확인 |
|---|---|---|---|
| 1.5.97 | 35565 + 0x748 | 67315 + 0x7B | 0x5b2ff0 / 0xc150b0 |
| 1.6.640 | 36564 + 0xC26 | 68617 + 0x7B | 0x5ec240 / 0xc4dda0 |
| 1.6.1170 | 36564 + 0xC26 | 68617 + 0x7B | 0x645ea0 / 0xcd8f40 |

CommonLibSSE-NG SE/AE SDK로 실제 DLL을 빌드했습니다. 설치된 각 버전 Address Library에서 위 ID의 존재와 RVA를 확인했습니다. **이는 실제 명령어·ABI 검증 완료를 뜻하지 않습니다.** 설치된 SE 실행 파일의 디스크 이미지에서는 해당 위치의 E8 명령어를 확인하지 못했습니다. 원인을 단정하거나 이를 근거로 오프셋을 바꾸지 않았습니다. AE 실행 파일과 실제 게임 실행 검증은 수행하지 않았습니다.

런타임은 두 콜사이트의 읽기/실행 범위·E8 명령·원래 목적지·변경 전 바이트를 확인합니다. 원래 함수와 점프 스텁을 먼저 완성한 후 두 후크를 설치하며, 실패 시 롤백을 시도하고 실패 상태에서는 재설치하지 않습니다. 준비 전 래퍼는 원래 함수를 호출합니다. 가상 함수 포인터도 사전 검증 후 갱신합니다. 임의 패턴 검색이나 추측 주소로 우회하지 않습니다. OS 메모리 보호 실패까지 롤백을 절대 보장할 수는 없습니다. 실제 ABI·다른 후킹 모드와의 상호작용은 게임에서 확인해야 합니다.

공식 참조: [CommonLibSSE-NG](https://github.com/CharmedBaryon/CommonLibSSE-NG), [OAR Hooks.cpp](https://github.com/ersh1/OpenAnimationReplacer/blob/main/src/Hooks.cpp), [SKSE Menu Framework API](https://github.com/QTR-Modding/SKSE-Menu-Framework-3-API). 참조 소스만으로 세 게임 버전의 실행 검증을 대신하지 않았습니다.

## Q5. UI 정리

- Dance Studio: 기존 곡 업데이트와 새 곡 추가를 분리하고, 게시 직전 구체적인 이전 출력 목록을 검토하도록 했습니다.
- 신뢰 가능한 Auto FOV가 없는 상태의 단일 선택 FOV 모드 컨트롤을 제거했습니다. 수동 FOV 값·설명은 유지합니다.
- Facial Studio: 기본 MFG 편집을 앞쪽의 펼쳐진 패널로 옮겼습니다. MFEE 편집·RaceMenu 가져오기·Solo 등은 유지합니다.
- 인게임: Facial Test와 개발용 재생 비교는 기본 숨김입니다. 필요한 경우 `SKSE/Plugins/DanceStudio.ini`의 `[Diagnostics] EnableDeveloperTools=1`로 활성화합니다. 예제 INI만 배포하며 기존 사용자 설정은 덮어쓰지 않습니다.
- 곡 목록의 기본 라벨은 제목 중심입니다. 선택 항목의 전체 제목과 ID는 별도로 확인합니다. 내부 선택 식별자는 그대로 유지합니다. 새 검색·즐겨찾기 기능은 추가하지 않았습니다.

`UI-이벤트-목록.csv`는 두 편집기의 버튼 helper 호출 지점 64곳과 연결 동작을 기록한 코드 점검표입니다. 모든 물리적 마우스 조작을 검증했다는 의미는 아닙니다.

## Q6. 측정한 성능 개선

동일 프로세스에서 기존 알고리즘을 재현한 함수와 새 함수를 비교했습니다. 10초/600개 비정렬 키·36개 모프, 600개 곡선 점을 사용했습니다. 1000개 시점 및 직접 데이터 변경 뒤 평가 결과 일치를 확인했습니다. 아래 수치는 이 컴퓨터의 해당 실행 결과이며 전체 앱 FPS 측정은 아닙니다.

| 작업 | 반복 | 이전 → 이후 시간 | 이전 → 이후 할당량 |
|---|---:|---|---|
| 클립 평가 | 3000 | 673.85 → 341.96 ms | 103,672,144 → 51,904,144 B |
| 강도 곡선 평가 | 20000 | 837.55 → 112.47 ms | 344,182,544 → 80 B |
| 채널 상태 비교 | 10000 | 141.34 → 16.49 ms | 58,496,488 → 80 B |

매 평가 정렬/배열 생성을 단일 탐색으로 바꾸고 JSON 직렬화 비교를 필드 비교로 바꿨습니다. 별도 캐시를 만들지 않아 이동·삭제·Undo/Redo 후 오래된 인덱스가 남지 않습니다. 보간·음악 시간·모프 정확도는 낮추지 않았습니다. 기존 타임라인의 재생 헤드만 이동시키는 구조는 유지했습니다. NIF/TRI 렌더러와 RaceMenu 복원은 이번에 변경하지 않았습니다. 렌더링 FPS 개선을 주장하지 않습니다.

## Q7. 기존 곡 호환성

`song.json` schema 3·4, facial timeline schema 1·2·3을 유지합니다. 프로젝트 schema 5는 유지하고 원본 지문 필드만 선택적으로 추가했습니다. 음악 샘플 기반 시계·춤/카메라 FPS·HKX 원본 보존·표정 Ledger·Photo Mode·기하 보정은 변경하지 않았습니다. 이전 곡은 지원 스키마와 유효한 파일/해시 조건에서 재내보내기 없이 읽습니다.

역사적 모든 패키지를 보장하지 않습니다. 남성용 춤 경로가 없는 오래된 여성 전용 패키지는 남성 재생을 위해 재내보내기가 필요합니다(기존 정책). song schema 1·2는 지원 범위가 아닙니다. 같은 토큰에 서로 다른 내용을 연결한 패키지는 안전을 위해 제외합니다. 기존 곡의 실제 게임 재생은 NOT TESTED입니다.

## 사용자가 게임에서 확인할 최소 체크리스트

1. 대상 버전에 맞는 SKSE/Address Library와 OAR·SKSE Menu Framework·MFG/MFEE 등 기존 선행을 설치하고 시작 로그에서 후크 성공/실패 및 대상 버전을 확인합니다.
2. 표정 없는 기존 곡과 MFG/MFEE 혼합 곡을 시작하고, 눈·입·감정의 구간 진입/종료를 확인합니다.
3. Space 일시정지·재개, 수동 정지·자연 종료, Photo Mode 진입/복귀 후 음악·춤·카메라와 표정 복원을 확인합니다.
4. 외부 표정 변경, 셀 이동·세이브 로드·취소 후 외부 값을 강제로 초기화하지 않는지 확인합니다.
5. 표정 파일을 누락/손상시킨 테스트 복사본에서 경고와 기존 음악·춤·카메라 계속 재생을 확인합니다.
6. 같은 곡을 업데이트하고 이전 출력 정리/유지/취소를 각각 확인한 뒤 재검색 결과와 실제 재생 대상을 확인합니다.

게임에서 문제가 나면 실행 버전, 곡의 id/exportId, LDA 로그와 재현 동작을 함께 기록합니다. 이 패키지는 코드·빌드 검사를 마친 공개 후보이며 게임 검증 완료본으로 표기하지 않습니다.
