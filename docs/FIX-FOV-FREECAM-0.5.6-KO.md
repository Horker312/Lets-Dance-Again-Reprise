# LDA:R 0.5.6 — 휠 FOV / 실제 자유카메라 수정

## 확인된 원인
2026-10-30 00:24 진단 로그에서 휠 ID 8/9, value=1이 정상 수신됐지만 입력 스레드는 13268·1376·8532 등이며 카메라 업데이트 스레드는 23656이었습니다. 기존 mainThread 일치 검사에서 모두 반환하여 FOV가 45로 유지됐습니다. 입력 장치 자체의 실패가 아니었습니다.
자유시점 준비 분기는 'existing game camera retained'만 수행하고 실제 자유카메라 진입 함수를 호출하지 않았습니다. 따라서 플레이어 중심의 기존 3인칭이 남았습니다.

## 변경
- 휠 콜백은 게임 객체를 읽거나 수정하지 않고 정수 방향만 고정 크기 128개 큐에 전달합니다. 카메라 업데이트 스레드가 현재 음악 시점의 원본 FOV와 큐를 평가해 적용합니다.
- FIFO, 상한, 중복 배출 방지, 세션/메뉴/Photo Mode 전환 비우기, 늦은 작업 콜백을 거부하는 상태 토큰을 추가했습니다.
- UI·Photo Mode·카메라 점유 검사는 업데이트 스레드에서 수행합니다. 자유시점에서는 휠 FOV 기능이 개입하지 않습니다.
- 같은 입력 디스패치의 Space 상태도 동시 접근에 안전하게 보호했습니다. 즉시 음소거/일시정지 정책은 유지합니다.
- 자유시점 선택 시 ToggleFreeCameraMode(false)를 실제 호출합니다. 게임 시간을 정지하지 않으며, 플레이어 기준 경로 보정/추적 없이 게임의 자유카메라 입력을 전달합니다.
- 자유카메라도 SmoothCam/TDM 점유를 정식 요청하고 종료 시 반환합니다. 타 모드 점유 중에는 무리하게 진입하지 않습니다.
- 원래 1/3인칭으로 복원합니다. Photo Mode 중 정지한 경우 자유카메라 종료를 인계 종료 이후로 유예하며, 다른 대상 카메라를 빼앗지 않습니다. 월드 변경 시 유예 상태를 버립니다.
- 새로운 게임 객체/입력 포인터를 작업 스레드 사이로 보관하지 않습니다. HKX·곡 패키지·음악·시간 매핑·스케일 보정은 변경하지 않았습니다.

## 검증
큐의 다중 스레드 입력, 순서, 용량 제한, 상태 전환, 늦은 콜백 거부, Space 중복 입력과 자유카메라 진입/복원 정책 검사 1021개 통과.
기존 준비·정리 3500개, 콘텐츠 선택 31개, Space/상태/추적 38개, Photo Mode 일시정지 정책 63개, 실제 WinMM 일시정지/재개 8개와 언어·버전 검사를 재통과했습니다.
DLL 빌드/버전 리소스/링크 및 SKSE export 검사 성공. 1.5.97·1.6.640·1.6.1170 Address Library에서 자유카메라 진입 함수 ID도 확인했습니다. 이는 해당 게임 실행 검증을 뜻하지 않습니다.
Dance Studio는 변경 없는 0.5.0입니다. 모드 풀버전에 곡 패키지는 포함하지 않습니다.

## 사용자 게임 확인
1. 전용 카메라 재생 중 휠을 위아래로 굴려 확대/축소되는지 확인하세요. Space 일시정지 중에도 동작해야 합니다.
2. 로그의 'Wheel FOV applied'에 실제 적용 스레드와 바뀐 desired 값이 남는지 확인하세요. 'FOV projection diagnostic'으로 목표/실제 worldFOV와 투영을 대조할 수 있습니다.
3. 자유시점을 선택한 후 WASD/마우스로 캐릭터에서 벗어나 자유롭게 이동하는지 확인하세요. 종료 시 원래 시점과 조작이 복구돼야 합니다.
4. Photo Mode 안에서 휠을 Reprise가 바꾸지 않는지, Photo Mode 도중 춤을 종료하고 닫았을 때 카메라가 정상 복구되는지 확인하세요.

실제 Skyrim에서 수정본을 실행한 검증은 아직 하지 않았습니다. 특히 실제 투영 FOV가 새 입력 값으로 반영되는지와 TFC 이동·타 카메라 모드 조합은 게임 확인이 필요합니다. AE 두 버전은 계속 시험 지원입니다.
